# Escenarios de validación

Usa estos casos como pruebas de decisión. Las rutas adicionales solo son válidas cuando su propio trigger o una dependencia obligatoria leída las justifique.

| Escenario                   | Señales y selección esperada                                                                                                                     | Descartes o gates clave                                                              |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Pregunta conceptual         | Pregunta sin artefacto ni ejecución; selecciona únicamente la skill temática específica, si existe                                               | Descarta `task-governance`; si no hay temática, `skill_resolution: none`             |
| Editar React visual         | Archivo/componente React más cambio visual; selecciona React, composición y políticas visuales coincidentes                                      | `Web` solo no basta; añade validación solo si su trigger aplica al cierre solicitado |
| Crear/revisar backoffice    | Backoffice, panel administrativo, shell o pantalla administrativa; selecciona `backoffice-application-patterns` y sus dependencias              | Carga solo la referencia del tipo de pantalla; no activa el shim histórico           |
| Crear landing page          | Página pública de marketing/conversión; selecciona `landing-page-patterns` y sus dependencias                                                    | No activa patrones administrativos; exige contenido y afirmaciones aprobadas         |
| MUI real sin capacidad      | Dependencias o archivos demuestran MUI, pero ninguna capacidad MUI instalada coincide por metadata; conserva las políticas agnósticas aplicables | Reporta `capacidad MUI ausente`; no reactives referencias heredadas ni inventes ruta |
| Mutación remota             | Mutación/cache/concurrencia de datos remotos; selecciona `remote-data-behavior` y contratos de implementación coincidentes                       | No infieras API backend sin endpoint o artefacto transversal                         |
| Validación UI en navegador  | Implementación UI renderizable al cierre; selecciona validación frontend y capacidad global Playwright                                           | Recorre y revisa visualmente sin crear archivos de prueba                            |
| Prueba de navegador pedida  | El usuario solicita pruebas de flujo/Playwright; selecciona política de pruebas y capacidad global Playwright                                     | Solo la solicitud explícita autoriza specs, fixtures, snapshots o baselines          |
| Auth o Storage              | Supabase Auth/Storage explícito; selecciona Supabase y workflow declarado por el contrato aplicable                                              | No añadas SQL/RLS/Postgres sin cambio de base de datos                               |
| SQL/RLS                     | Migración, SQL, esquema o RLS; selecciona Supabase, workflow, prácticas Postgres y arquitectura backend que correspondan                         | Bloquea si falta una dependencia obligatoria                                         |
| Pipeline Web-only           | Pipeline o preview Web sin recurso Supabase; selecciona contratos Web/pipeline que coincidan                                                     | No actives delivery Supabase por `Web` o `pipeline` genérico                         |
| Delegación                  | Lanzar, coordinar o verificar agentes; selecciona `agent-orchestration` y sus dependencias obligatorias                                          | Entrega rutas exactas; no copies resúmenes                                           |
| Alcance que crece           | Empieza con UI React y luego incorpora mutación remota; reevalúa y añade `remote-data-behavior` más dependencias                                 | No conserves ni añadas skills sin evidencia vigente                                  |

En flujo normal verifica selección y aplicación sin reporte ceremonial. Para delegación, bloqueo, ambigüedad, cambio de alcance o auditoría, verifica que el recibo incluya señales relevantes, rutas seleccionadas, dependencias, bloqueos y `reevaluar_cuando`. Verifica además detección de ciclo, ruta obligatoria ausente y fallback de solo frontmatter.
