# UI profile selection

Classify the UI on independent axes before selecting a profile. Record evidence from the accepted requirement and existing project rather than choosing from visual novelty.

| Axis | Values | Decision evidence |
|---|---|---|
| Product surface | backoffice, product web, marketing website, commerce | users, tasks, information hierarchy, conversion or operational goals |
| Platform | responsive web, native mobile, desktop | runtime, input methods, navigation model, supported viewports |
| Composition | data-heavy, transactional, content-led, analytical | dominant records, actions, reading, metrics, or workflows |
| Density | compact, default, comfortable | task frequency, data volume, input precision, accessibility needs |

The V1 `backoffice` profile applies when authenticated users repeatedly manage records, workflows, settings, permissions, reports, or operational metrics. Responsive mobile behavior remains part of this profile; it does not turn the product into a native-mobile profile.

If the surface is not backoffice, report the required profile extension. Continue only work that is independent of its visual and composition decisions.
