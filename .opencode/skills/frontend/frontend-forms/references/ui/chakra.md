# chakra — shared form contract integration

Inherits `../../SKILL.md`; this reference supplies the selected UI binding only.

Apply `frontend-forms` with the installed major's field composition. In v2 inspect FormControl/label/helper/error APIs; in v3 inspect compound Field/recipe APIs. Do not mix their prop names. Bind required/invalid metadata and consistent danger treatment to the whole field anatomy.

Keep Chakra primitives inside project-owned field variants when shared composition or behavior is required. Use supported input grouping/adornments and an actual icon button with the adopted visibility icon pair for mandatory password visibility; visible `Show`/`Hide` text is not the icon control. For select mode use an accessible custom popup select compatible with the installed major; a NativeSelect is not the default custom-popup contract. For searchable mode use combobox capability available in that version or a justified compatible primitive.

Map actual input/trigger refs for failed-submit focus. Choose the installed-version dialog/calendar capability for date selection and assess phone/mask integration when missing. Generic base fields consume backend/form state; feature adapters own remote requests and error-path parsing.
